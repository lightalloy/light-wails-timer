# Design

## Context

Проект создаётся с нуля в пустом каталоге. Мотивация — в `proposal.md`, требования — в `specs/timer`, `specs/tray-ui`, `specs/desktop-integration`.

Факты об окружении, которые влияют на решения (проверены на машине разработчика):

- XFCE 4.18, сессия X11 (`xfce4-panel` 4.18.4), GTK 3.24.38.
- GTK4 и `webkitgtk-6.0` отсутствуют; есть `libwebkit2gtk-4.0`, `libwebkit2gtk-4.1` (runtime) и `libsoup-3.0` (runtime), но нет dev-пакетов `libwebkit2gtk-4.1-dev` и `libsoup-3.0-dev`.
- `xfce4-notifyd` 0.8.2 установлен; демон запускается через D-Bus, `notify-send` отрабатывает.
- Установлены Go 1.24.3 и Wails v2.11.0; CLI `wails3` нет.
- `go.mod` Wails v3.0.0 требует Go 1.26.0; начиная с `v3.0.0-alpha.93` Linux-сборка по умолчанию использует GTK4, а GTK3 доступен по тегу `gtk3`.

## Goals / Non-Goals

**Goals:**

- Один процесс и один бинарник: трей, окно и таймер живут в нём; нет фонового демона.
- Ядро таймера детерминировано и тестируется без GUI: время подставляется через интерфейс часов.
- Состояние имеет единственный источник истины — Go-сторона; фронтенд только отображает снапшоты.
- Кроссплатформенность достигается использованием платформенных API Wails (трей, уведомления, автозапуск, single instance), без собственного Linux-кода.

**Non-Goals:**

- Несколько таймеров, помидорные циклы, история/статистика, звуковые сигналы, локализация кроме русской.
- Упаковка и распространение (AppImage/deb/установщик), автообновление.
- Приёмка на Windows и macOS: код должен собираться и не содержать Linux-only вызовов, но тестируется только Linux/XFCE.
- Идеальное поведение на Wayland: позиционирование окна у иконки опирается на X11-курсор и может центрироваться.

## Decisions

### D1. Wails v3.0.0 и vanilla TypeScript

Берём стабильный `github.com/wailsapp/wails/v3@v3.0.0` и шаблон `vanilla` (Vite + TypeScript, без фреймворка). UI маленький (три кнопки, кольцо, текст), фреймворк дал бы лишнюю зависимость и вес сборки.

Альтернативы: Wails v2 — не отвечает запросу «попробовать wails3»; Tauri/Electron — тяжелее и потребовали бы Rust/большой runtime.

### D2. Сборка с тегом `gtk3`

Wails v3 по умолчанию собирается под GTK4/`webkitgtk-6.0`, которых в системе нет. Собираем с `-tags gtk3`: тогда cgo-зависимости — `gtk+-3.0`, `webkit2gtk-4.1`, `gdk-3.0`. Требуются dev-пакеты `libwebkit2gtk-4.1-dev`, `libsoup-3.0-dev`.

Тег фиксируется в Taskfile проекта (переменная сборки), чтобы `wails3 build`, `wails3 dev` и `go build` не расходились. Альтернатива — установить GTK4 и `webkitgtk-6.0-dev` и собирать по умолчанию; отклонено: окружение XFCE уже на GTK3, лишние пакеты и риск несовместимости тем.

Последствие: бинарник зависит от `libwebkit2gtk-4.1`; при будущем переходе Wails на GTK4-only потребуется миграция.

### D3. Go 1.26 через `GOTOOLCHAIN=auto`

В `go.mod` приложения указываем `go 1.26.0`, в README — `GOTOOLCHAIN=auto` (Go скачает 1.26.10 при первой сборке) либо установка Go 1.26 вручную. Альтернатива — старый alpha-релиз Wails с Go 1.24; отклонено: нестабильный API и отсутствие фиксов.

### D4. Ядро таймера: дедлайн + внедряемые часы

Состояние — конечный автомат `idle` ↔ `running`. В `running` хранится `deadline time.Time` и `presetMinutes`. Остаток считается как `max(0, deadline - clock.Now())`, поэтому сон, простой и перевод часов обрабатываются естественно.

- Один goroutine с тикером 1 с: пересчитывает остаток, при `now >= deadline` выполняет завершение ровно один раз.
- Завершение: атомарно перевести в `idle`, очистить персистентное состояние, разослать снапшот, отправить уведомление.
- Запуск при активном таймере заменяет `deadline` и пресет, не порождая уведомления.
- Часы — интерфейс `Clock` с реализациями `realClock` и `fakeClock` для тестов.

Альтернатива: считать декрементом счётчика в памяти — отклонено: врёт после сна и перезапуска.

### D5. Персистентность: XDG state, атомарная запись

`$XDG_STATE_HOME/light-wails-timer/state.json` (fallback `~/.local/state/light-wails-timer/state.json`), права `0600`, версия схемы:

```json
{"version": 1, "presetMinutes": 30, "startedAt": "2026-10-31T15:00:00+03:00", "deadline": "2026-10-31T15:30:00+03:00"}
```

Запись — только при переходах (старт, замена, стоп, завершение), атомарно: временный файл в том же каталоге + `rename`. Чтение устойчиво к мусору: ошибка парсинга → `idle`, запись в лог, файл перезаписывается при следующем переходе.

Догоняющее уведомление (catch-up): при загрузке, если `deadline <= now`, состояние очищается и отправляется одно уведомление «интервал завершился, пока приложение было закрыто». Порядок важен: служба уведомлений инициализируется до чтения состояния.

### D6. Трей: два PNG-значка и SNI-подсказка

`app.SystemTray.New()`, `SetIcon` с встроенными через `go:embed` PNG 32×32 (и 64×64 для HiDPI — берём 64×64 с прозрачностью, панель масштабирует): серый `#9AA0A6` и зелёный `#34A853`, с тонкой обводкой, чтобы читались на светлой и тёмной панели.

- `SetLabel` и `SetTooltip` получают один и тот же текст `light-wails-timer — 24:59`, обновляются при изменении текста (раз в секунду), а не безусловно на каждом тике: повторная публикация свойств заставляет панель сбрасывать подсказку. На Linux заголовок элемента несёт тот же текст, потому что XFCE показывает только его, а не описание `ToolTip`.
- `AttachWindow(window)` + `WindowOffset(8)` и явный `OnClick` → `ToggleWindow`: на Windows и macOS первичный щелчок открывает и скрывает окно.
- Меню пересобирается целиком при каждой смене состояния, а не на каждом тике: в `idle` оно содержит три пункта «Запустить на N минут», в `running` — «Остановить». Подсказка обновляется дёшево, перестройка D-Bus-меню — нет. Статусная строка без секунд: «Таймер активен (30 мин)» / «Таймер неактивен».

На Linux Wails использует StatusNotifierItem. Проверка на XFCE 4.18 показала: плагин Status Tray показывает меню по первичному щелчку и не передаёт приложению `Activate`, поэтому окно на XFCE открывается пунктом «Показать окно» (а также повторным запуском и флагом `--show`); подсказка отображает заголовок элемента. Для панелей, передающих `Activate`, обработчик переключает окно как обычно.

### D7. Окно-попап 300×360

`WebviewWindowOptions{Width: 300, Height: 380, Frameless: false, AlwaysOnTop: true, DisableResize: true, HideOnFocusLost: true, HideOnEscape: true, Hidden: true}`. Окно получает стандартный заголовок с кнопкой закрытия; `DisableResize` убирает кнопку разворачивания, потому что вёрстка рассчитана на фиксированный размер. Событие `WindowClosing` перехватывается: `event.Cancel()` + `window.Hide()`, поэтому крестик сворачивает окно в трей, а не завершает процесс. Окно скрывается, а не закрывается, поэтому процесс живёт; на macOS выставляем `ApplicationShouldTerminateAfterLastWindowClosed: false`.

Позиционирование выполняет Wails (`PositionWindow`) по координатам клика из SNI; если панель их не передала, используется позиция курсора (X11). На Wayland окно может появиться по центру — приемлемо.

### D8. Уведомления через сервис Wails

`notifications.New()` регистрируется сервисом; отправка — `SendNotification` с `ID: "timer-finished"`, заголовком «Таймер завершён», текстом «Интервал 30 минут истёк» и `Sound: &NotificationSound{Silent: true}` (пользователь выбрал только уведомление, без звука).

Порядок при завершении: сначала сброс состояния и персистентности, затем уведомление. Если D-Bus вернул ошибку (нет демона), приложение остаётся в `idle`, ошибка пишется в stderr, а в окне выставляется баннер «Не удалось показать уведомление». Баннер снимается при следующем запуске таймера или закрытии окна.

Альтернатива: `notify-send` через exec — отклонено: теряется кроссплатформенность и управление ID.

### D9. Автозапуск через `app.Autostart`

Используем встроенный `AutostartManager` Wails: `Enable()`, `Disable()`, `IsEnabled()`, `Status()`. Состояние чекбокса в меню всегда читается из `IsEnabled()`, а не из локального флага, поэтому внешнее удаление регистрации отражается корректно.

На Linux создаётся `~/.config/autostart/light-wails-timer.desktop` с абсолютным путём к исполняемому файлу (Wails резолвит симлинки); на macOS — LaunchAgent, на Windows — ключ реестра. Ошибки регистрации показываются в окне, чекбокс остаётся выключенным.

### D10. Один экземпляр

```go
application.Options{
  SingleInstance: &application.SingleInstanceOptions{
    UniqueID: "app.lightwailstimer.timer",
    OnSecondInstanceLaunch: func(application.SecondInstanceData) { showWindow() },
  },
}
```

Второй процесс показывает окно первого и выходит с кодом 0 (по умолчанию `ExitCode`).

### D11. Контракт Go ↔ фронтенд

Сервис `TimerService` с методами `Start(minutes int) error`, `Stop() error`, `GetState() State`. Любое изменение и каждый тик публикуют событие `timer:state` со снапшотом:

```go
type State struct {
    Status        string // "idle" | "running"
    PresetMinutes int
    RemainingSec  int
    TotalSec      int
}
```

Фронтенд не ведёт собственный таймер: рисует снапшот и анимирует кольцо CSS-переходом между тиками. Это гарантирует согласованность окна и подсказки с точностью до одной секунды.

### D12. Русские строки в одном месте

Go: `internal/i18n/ru.go`; TS: `frontend/src/strings.ts`. Библиотеку i18n не подключаем — строк немного, а централизация оставляет путь к локализации.

### D13. Структура проекта

```
main.go                     — сборка приложения, трей, окно, single instance
internal/timer/             — автомат, часы, пресеты, тесты
internal/store/             — чтение/запись состояния, XDG-пути, тесты
internal/service/           — TimerService: биндинги и события
internal/i18n/              — русские строки
assets/                     — icon-idle.png, icon-active.png (go:embed)
frontend/                   — vanilla TS: кольцо, кнопки, форматирование
```

## Risks / Trade-offs

- **Wails v3.0.0 — свежий релиз, API может меняться** → версия зафиксирована в `go.mod` и README, используем минимальную поверхность API, обновление — отдельным изменением.
- **Нужен Go 1.26, локально 1.24.3** → `GOTOOLCHAIN=auto` тянет тулчейн при первой сборке; офлайн-сборка требует заранее установленного Go 1.26 (отмечено в README).
- **GTK3-путь в Wails помечен как legacy** → при обновлении Wails возможен переход на GTK4; изоляция в одном теге сборки упрощает миграцию.
- **Подсказка SNI на XFCE может не отображаться** → остаток дублируется в окне; проверка входит в ручную приёмку.
- **Иконка не появится без плагина Status Notifier** → README описывает, как включить плагин в `xfce4-panel`; запасной путь — запуск с флагом `--show`, открывающим окно сразу.
- **Тикер не работает во время сна** → завершение обрабатывается на первом тике после пробуждения, уведомление может опоздать на секунды; это следствие выбранной модели стенных часов и приемлемо.
- **Демон уведомлений может стартовать позже приложения при автозапуске** → ошибка логируется, состояние сбрасывается корректно; повторное уведомление не шлём.
- **Смена системного времени назад** → остаток временно увеличивается; таймер всё равно завершится по дедлайну. Поведение задокументировано, отдельной логики не добавляем.

## Migration Plan

Изменение создаёт приложение с нуля, миграции данных нет. Откат — удаление каталога проекта; пользовательские файлы (`~/.local/state/light-wails-timer/`, `~/.config/autostart/light-wails-timer.desktop`) удаляются вручную и описаны в README. Версия схемы состояния (`version`) заложена для будущих миграций.

## Open Questions

- Упаковка в AppImage/deb и иконка приложения для меню — отдельное изменение после приёмки.
- Отображение кольца прогресса на самой иконке трея (динамическая пиксмапа) — отдельное изменение, если понадобится.
- Переключатель звука уведомления — отдельное изменение.
